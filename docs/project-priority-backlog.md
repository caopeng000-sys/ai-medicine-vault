# 项目待完成任务优先级清单

本文档用于跟踪 AI 家庭药箱项目从当前可用版本走向正式上线版本所需补齐的任务。优先级按上线风险排序：P0 为上线前必须完成，P1 为重要但可分阶段上线，P2 为后续增强。

## 当前状态

项目已经具备以下基础能力：

- Next.js + TypeScript 应用基础结构
- 药品管理：新增、编辑、删除、搜索、分类筛选、分页、图片上传与预览
- 药品 AI 图片识别与字段回填
- 成员管理与病历记录基础能力
- AI 助手基础意图识别：药品库查询、病历查询方向
- Prisma 数据模型与本地数据库
- Auth.js 登录基础结构
- 部分 API 安全加固、导出能力、自动化测试与上线运维文档

当前仍有一批未提交的本地改动，主要包括 API 写接口安全增强、导出能力、登录体验、Playwright 回归测试框架和上线运维文档。正式推进前建议先完成验证，再按需要提交远程。

## P0 上线前必须完成

### 1. 真实登录与权限闭环

目标：

- 完成真实 OAuth 登录配置
- 确认生产环境不存在开发兜底登录
- 所有用户数据按登录用户隔离
- 登录后具备明确的用户态展示、退出登录能力

当前状态：

- Auth.js 已接入
- Prisma Adapter 已接入
- 生产 OAuth 配置仍待完成
- 登录体验仍需继续完善

验收标准：

- 未登录用户无法访问核心业务页面
- 登录用户只能访问自己的家庭成员、药品、病历数据
- 生产环境禁用开发兜底身份
- 支持退出登录

### 2. 生产数据库

目标：

- 将本地开发数据库迁移到生产级 PostgreSQL
- 建立稳定的迁移、备份和恢复流程

当前状态：

- 本地 Prisma 数据模型可用
- 生产数据库服务尚未接入

验收标准：

- 生产环境通过 `DATABASE_URL` 连接 PostgreSQL
- Prisma migration 可在生产环境执行
- 有明确的备份与恢复说明
- 数据库凭据不进入 Git 仓库

### 3. 药品图片持久化存储

目标：

- 药品图片不依赖本地文件系统
- 部署后图片仍可稳定访问
- 支持后续扩展到多设备访问

当前状态：

- 本地图片上传和展示能力已做过修复
- 生产对象存储尚未接入

验收标准：

- 图片上传到对象存储
- 数据库保存图片访问地址或对象 key
- 删除药品时可按策略处理对应图片
- 图片在重新部署后不丢失

### 4. API 安全统一收口

目标：

- 所有写接口都进行登录校验、权限校验、参数校验和统一错误返回

当前状态：

- 部分写接口已经开始加固
- 仍需覆盖单条资源、图片上传、AI 调用等接口

验收标准：

- 未登录请求不能写入数据
- 跨用户资源访问被拒绝
- 参数错误返回结构一致
- 自动化测试覆盖核心写接口

### 5. 自动化回归测试完整跑通

目标：

- 用 Playwright 建立可重复执行的核心回归测试
- 覆盖药品管理、成员管理、病历、AI 助手关键路径

当前状态：

- E2E 测试框架已开始搭建
- 浏览器依赖和完整 E2E 执行仍需最终跑通

验收标准：

- `npm run test:e2e` 可稳定执行
- 至少覆盖药品新增、编辑、删除、搜索、图片预览
- 测试报告可沉淀到 `docs/`
- CI 中可选接入 E2E

## P1 重要但可分阶段完成

### 1. CI/CD 发布流程

目标：

- 每次提交后自动执行质量检查
- 降低发布前人工检查成本

建议内容：

- TypeScript 类型检查
- 单元测试
- Next.js 构建
- 可选 E2E 测试
- 环境变量完整性检查

验收标准：

- Pull Request 或 push 后自动执行检查
- 检查失败时不允许发布
- 有明确的部署流程文档

### 2. AI 助手能力增强

目标：

- 让 AI 助手从固定问答走向稳定的家庭健康助理

建议内容：

- 扩展更多意图：药品查询、病历查询、复诊准备、过期药提醒
- AI 意图识别输出结构化 JSON
- 查询结果和数据库真实数据绑定
- AI 失败时有友好降级提示

验收标准：

- 能识别「家里有哪些止咳药」这类泛化药品查询
- 能识别「我上次什么时候感冒」这类病历查询
- 不再依赖简单关键词硬编码
- 关键 AI 调用有日志记录

### 3. 药品管理继续产品化

目标：

- 从简单药品列表升级为可长期维护的家庭药品库

建议内容：

- 批号、有效期、库存变动记录
- 药品归档
- 过期提醒
- 重复药品合并
- 药品详情页

验收标准：

- 药品库存变化可追踪
- 即将过期和已过期药品可准确筛选
- 同名药品有明确处理策略

### 4. 数据导出与备份体验

目标：

- 用户可以拿走自己的数据
- 就诊前可以快速整理材料

建议内容：

- JSON / CSV 导出
- 按成员导出
- 按时间范围导出
- 复诊材料包
- 后续可扩展 PDF

验收标准：

- 导出数据来自真实数据库
- 导出内容可读、字段完整
- 不会导出其他用户数据

### 5. 错误监控与运行日志

目标：

- 线上出错时能定位问题
- AI、上传、数据库错误可追踪

建议内容：

- 接入 Sentry 或同类错误监控
- 记录 AI 调用日志
- 记录图片上传失败原因
- 关键接口保留 request id

验收标准：

- 前端运行异常可在监控平台看到
- 服务端接口异常可追踪
- AI 调用失败有明确日志

## P2 后续增强

### 1. 家庭多人协作

目标：

- 支持多人共同维护同一个家庭药箱

建议内容：

- 家庭空间
- 成员邀请
- 权限分级
- 操作记录

### 2. 提醒系统

目标：

- 从资料管理升级到主动提醒

建议内容：

- 用药提醒
- 复诊提醒
- 药品过期提醒
- 库存不足提醒

### 3. 更完整的健康档案

目标：

- 让病历、检查报告、药品记录形成统一健康档案

建议内容：

- 检查报告上传
- 过敏史、慢病史、长期用药记录
- 就诊记录结构化
- 家庭成员健康时间线

### 4. AI 药箱知识库

目标：

- 让 AI 结合说明书、历史用药和病历进行更可靠的问答

建议内容：

- 药品说明书结构化
- 药品适应症与禁忌查询
- 病历与药品联合检索
- RAG 或向量检索能力

### 5. 移动端体验优化

目标：

- 优化手机端录药、拍照、查询体验

建议内容：

- 移动端拍照录入流程
- 卡片布局优化
- 大按钮和单手操作
- 图片压缩与上传进度

## 推荐执行顺序

1. 先完成当前未提交改动的验证：构建、单元测试、E2E 基础测试。
2. 补齐 P0 中不依赖外部服务的事项：API 安全、E2E、登录体验。
3. 等外部服务准备好后，接入生产数据库、对象存储、OAuth。
4. 建立 CI/CD 和监控。
5. 再扩展 AI 助手、提醒、家庭协作等 P1 / P2 能力。
