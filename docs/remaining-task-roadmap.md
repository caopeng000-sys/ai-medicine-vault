# 当前剩余任务路线图

本文档只列出当前项目里还没收尾的事项，并且按优先级和执行责任拆开，方便后续继续推进。

## 当前状态

已经完成的基础能力：

- Next.js + TypeScript 主体工程
- 成员、病历、药品、过敏、就医准备等核心数据页
- 药品管理：新增、编辑、删除、搜索、分类、分页、图片、AI 识别
- AI 助手：药品查询、病历查询、过敏史、用药说明、就医准备
- Auth.js 登录基础结构和登录态展示
- 本地 PostgreSQL 方案
- 药品图片本地存储 + S3 兼容对象存储抽象
- 自动化测试和构建验证
- GitHub Actions CI 已覆盖 Prisma 校验、单测、构建和 E2E

## P0

### 1. 真实 GitHub OAuth 配置

这项必须由你配合开通。

你需要做什么：

- 在 GitHub 创建 OAuth App
- 获取 `AUTH_GITHUB_ID`
- 获取 `AUTH_GITHUB_SECRET`
- 准备生产环境用的 `AUTH_SECRET`

我这边可以继续做什么：

- 补登录页文案和错误提示
- 校验登录跳转流程
- 把生产环境回调地址写进部署说明

### 2. 生产 PostgreSQL 接入

这项必须由你选择数据库服务并提供连接串。

你需要做什么：

- 选择 Supabase、Neon、Railway、Render 或其他 PostgreSQL 服务
- 创建生产数据库
- 提供 `DATABASE_URL`

我这边可以继续做什么：

- 保持 Prisma schema 和迁移脚本可用
- 帮你检查生产迁移命令
- 补数据库备份和恢复说明

### 3. 生产对象存储接入

这项必须由你开通对象存储服务并提供访问凭据。

你需要做什么：

- 开通阿里云 OSS、Cloudflare R2、AWS S3 或兼容服务
- 创建 bucket
- 提供访问密钥和 endpoint
- 决定公开读还是签名访问

我这边可以继续做什么：

- 保持图片存储接口兼容本地和 S3
- 补生产环境变量模板
- 补对象存储部署检查清单

### 4. 生产部署平台上线

这项需要你选择部署平台并完成绑定。

你需要做什么：

- 选择 Vercel、Railway、Render 或自建服务器
- 绑定 GitHub 仓库
- 配置环境变量
- 回填 OAuth 回调地址

我这边可以继续做什么：

- 整理部署步骤文档
- 检查构建和迁移命令
- 帮你确认线上访问入口

### 5. 回归测试最终固化

这项我可以继续做，但需要最终验证环境稳定。

我可以继续做什么：

- 扩 Playwright 覆盖范围
- 把核心回归测试整理成固定报告
- 把测试命令写入 CI

你可能需要配合什么：

- 确认浏览器依赖和数据库环境稳定
- 允许我在当前机器继续跑完整 E2E
