# AI 助手意图路由设计

日期：2026-04-27  
状态：草案

## 1. 背景

当前项目已经具备药品库、病历、过敏记录和就医准备等基础数据。下一步要把 `AI 助手` 从“泛问答”收敛成“基于资料的智能路由器”。

第一版只支持两个高频意图：

- `上次什么时候感冒`
- `家里有哪些抗过敏药`

AI 的职责不是直接自由回答，而是：

1. 识别用户意图
2. 路由到对应数据源
3. 基于真实数据组织答案
4. 给出来源依据
5. 对无法识别的问题给出友好兜底提示

## 2. 目标

### 2.1 功能目标

- 识别用户问题是否属于两个支持的意图
- 支持从病历中查询“最近一次感冒/类似感冒症状”的记录
- 支持从药品库中查询“抗过敏药”相关条目
- 回答中必须附带来源依据
- 无法识别意图时返回友好提示，不输出误导性答案

### 2.2 非目标

- 不做自由聊天
- 不做诊断
- 不做治疗建议
- 不做药物替代推荐
- 不扩展到更多意图，第一版只保留两个意图

## 3. 交互范围

### 3.1 支持的问题示例

- 我上次什么时候感冒
- 我最近一次感冒是什么时候
- 家里有哪些抗过敏药
- 有哪些抗过敏的药

### 3.2 不支持的问题示例

- 我是不是得了流感
- 我该吃什么药
- 这种药能不能替代另一种药
- 现在适合不适合用药

对于不支持的问题，系统返回：

“这类问题我现在还不支持。你可以问我上次什么时候感冒，或者家里有哪些抗过敏药。”

## 4. 方案

### 4.1 推荐方案：AI 识别 + 工具查库 + AI 整理答案

流程如下：

1. 用户在 `AI 助手` 页面输入问题
2. 后端调用阿里百炼模型做意图识别
3. 如果识别到支持的意图，后端查询对应数据源
4. 后端把查询结果交给模型整理成自然语言回答
5. 前端展示答案和来源依据

### 4.2 意图分类

第一版只定义三个结果：

- `recent_cold_record`
- `antiallergic_medicine_query`
- `unsupported`

## 5. 数据路由

### 5.1 `recent_cold_record`

检索数据源：

- 病历记录

检索规则：

- 优先找最新的、包含感冒相关关键词的记录
- 关键词包括但不限于：感冒、上呼吸道感染、流涕、鼻塞、咳嗽、发热
- 如果没有明确命中，但病历中最近一次相关记录足够明确，也可作为候选

输出内容：

- 记录时间
- 成员姓名
- 病历标题或诊断
- 记录摘要
- 来源说明

### 5.2 `antiallergic_medicine_query`

检索数据源：

- 药品库

检索规则：

- 优先匹配药品分类为抗过敏
- 其次匹配用途、使用说明、治疗疾病中包含过敏、鼻炎、荨麻疹、皮疹等信息的药品
- 如条目存在 AI 识别摘要，也可以作为辅助判断依据

输出内容：

- 药品名称
- 分类
- 规格
- 用法用量或使用说明
- 所属成员
- 来源说明

### 5.3 `unsupported`

当模型无法稳定判断意图时，直接返回友好提示，不进行数据查询。

## 6. 接口设计

新增后端接口：

- `POST /api/assistant/query`

请求体：

- `question`: 用户原始问题

响应体：

- `intent`: 识别结果
- `answer`: 最终回答
- `sources`: 来源列表
- `message`: 兜底提示或辅助说明

## 7. 前端交互

`/assistant` 页面保留一个输入框和结果区：

- 用户提交问题
- 页面显示识别后的答案
- 页面显示来源记录
- 页面显示无法识别时的提示

如果识别成功但没有查到数据，显示：

“我找到了这个问题对应的方向，但暂时没有查到可用记录。”

## 8. 错误处理

### 8.1 模型识别失败

- 返回兜底提示
- 不要伪造答案
- 不把失败当作成功回答输出

### 8.2 数据库无结果

- 返回“暂未找到对应记录”
- 同时提示用户可以换一种问法

### 8.3 数据源异常

- 病历或药品库查询失败时，返回明确的服务异常提示
- 不混淆为“没有数据”

## 9. 安全与边界

- AI 只负责识别和整理，不做诊断
- 所有回答必须基于真实数据
- 回答必须带来源依据
- 对无法识别的问题，不进行自由发挥
- API Key 仅放本地环境变量，不写入仓库

## 10. 验收标准

第一版验收以这两个场景为准：

1. 用户问“我上次什么时候感冒”
   - 能识别意图
   - 能查到对应病历
   - 能返回带依据的答案

2. 用户问“家里有哪些抗过敏药”
   - 能识别意图
   - 能查到药品库中的相关药品
   - 能返回带依据的答案

3. 用户问未支持的问题
   - 能返回友好提示
   - 不输出误导性医学结论

## 11. 后续扩展

如果第一版稳定，后续可以再加：

- 更多病历问法
- 更丰富的药品知识问答
- 与过敏记录、就医准备清单联动
- 更细的来源展示
