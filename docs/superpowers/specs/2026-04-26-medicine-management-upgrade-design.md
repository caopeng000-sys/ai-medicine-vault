# 药品管理升级设计文档

## 背景

当前药品管理已经具备基础能力，包括：

- 药品新增、编辑、删除
- 本地图片上传
- 阿里百炼图片识别回填
- 图片写入数据库
- 基于数据库的真实搜索
- 药品卡片预览

但从“家庭健康资料台”的目标来看，现有页面更像药品资料列表，还没有完全进入“家庭药箱管理”的状态。后续最有价值的方向，不是立即引入复杂的批次库存系统，而是先让用户更快知道：

- 这是什么药
- 还剩多少
- 放在哪里
- 该不该尽快处理

本设计的目标是在**保持单条主记录模式**的前提下，把药品管理补强为更实用、更清晰、更适合家庭场景的药箱首页，同时为未来批次能力预留扩展口。

## 目标

### 产品目标

- 让药品页成为真正的“家庭药箱首页”
- 让药品状态、库存、位置和有效期一眼可见
- 让搜索和筛选真正服务于查找药品
- 继续保留图片预览和 AI 识别能力
- 不打破当前单条主记录结构，为后续批次扩展留接口

### 用户目标

- 快速找到某个药品
- 快速判断某个药是否快过期或已过期
- 快速知道药品放在哪里
- 快速查看药品图片和 AI 摘要
- 后续如果需要，再把同名药拆成多个批次

## 非目标

- 第一版不做完整仓库式批次管理
- 第一版不做出入库流水
- 第一版不做药品替代推荐
- 第一版不做剂量诊断或医疗结论
- 第一版不强制用户重新整理全部历史药品

## 方案选型

### 方案 A：轻量增强版

沿用单条药品记录，只补库存、位置、状态和提醒。

优点：

- 改动小
- 最快落地
- 对现有页面影响最小

缺点：

- 后续批次扩展需要再补一层模型

### 方案 B：直接批次版

当前就把药品管理改成批次驱动，同名药拆成多个批次。

优点：

- 结构最完整

缺点：

- 第一版复杂度高
- 页面、录入和筛选都会变重

### 方案 C：推荐方案，单条主记录 + 预留批次扩展

继续把“一条药品记录”作为主展示单元，补足库存、位置和状态；同时在数据结构和页面信息组织上为后续批次扩展预留接口。

优点：

- 最适合当前阶段
- 落地快
- 后续能平滑升级

缺点：

- 第一版还不能表达同名药的多批次细节

**结论：采用方案 C。**

## 数据设计

### 继续保留的字段

现有药品记录继续保留以下信息：

- `name`：药品名称
- `category`：分类
- `dosage`：剂量
- `specification`：规格
- `instructions`：使用说明
- `purpose`：治疗疾病 / 适应症
- `expiresAt`：有效期
- `memberId`：所属成员
- `imageBytes` / `imageMimeType` / `imageName`：药品图片

### 建议强化的字段

这一版建议让以下信息更明确、更可编辑：

- `quantity`：库存数量
- `storageLocation`：存放位置
- `usageNote`：使用上下文说明
- `safetyNote`：安全提醒

其中：

- `quantity` 继续作为单条主记录的库存值
- `storageLocation` 要在前台显式可编辑
- `usageNote` 和 `safetyNote` 可继续由系统写入默认值，但需要在页面上更明显地展示

### 状态计算

药品状态建议由系统自动计算，不手工选择：

- `已过期`：`expiresAt < today`
- `即将过期`：`0 <= daysLeft <= 60`
- `库存不足`：`quantity <= 1` 或数量不可用时按业务规则降级
- `正常`：其他情况

状态优先级建议为：

1. 已过期
2. 库存不足
3. 即将过期
4. 正常

### 批次预留

第一版不做批次 UI，但建议在数据和代码组织上预留：

- 未来可在药品主记录下挂一层 `batch` / `stockLot`
- 当前 `quantity` 先表示主记录总量
- 未来做批次时，主记录可继续作为“药品名称/用途/图片”的聚合实体

## 页面设计

### 药品列表页

药品页要从“资料卡列表”升级为“家庭药箱首页”。

建议保留并增强的模块：

- 顶部统计卡
  - 药品总量
  - 即将过期
  - 已过期
  - 库存不足
- 搜索区
  - 名称
  - 成分 / 剂量
  - 用途
  - 成员
  - 存放位置
- 筛选区
  - 状态
  - 分类
  - 存放位置
  - 是否有图片
- 排序区
  - 已过期优先
  - 即将过期优先
  - 库存不足优先
  - 最近新增
- 卡片区
  - 药品名称
  - 所属成员
  - 分类
  - 库存数量
  - 存放位置
  - 有效期状态
  - 图片预览
  - 编辑 / 删除

### 药品编辑弹窗

编辑弹窗需要继续保持“快速录入工具”的定位。

建议调整为：

- 图片选中后直接预览
- 点击预览图可重新选择图片
- 数量与单位更清晰
- 存放位置前置展示
- 保存后自动关闭
- 编辑模式保留原图片和原字段

### 药品详情呈现

第一版不强制新增独立详情页，但卡片内建议展示更多信息：

- 原图预览
- 库存数量
- 存放位置
- 过期提示
- AI 摘要或识别备注

未来如果补详情页，优先用于：

- 查看更大图
- 查看批次信息
- 查看历史编辑记录

## 搜索与筛选设计

### 搜索范围

药品搜索应使用真实数据库查询，支持以下字段的模糊匹配：

- 药品名称
- 分类
- 剂量
- 使用说明
- 治疗疾病 / 适应症
- 规格
- 存放位置
- 使用备注
- 安全提示
- 成员名称

### 筛选项

建议支持以下筛选：

- 状态：正常 / 即将过期 / 已过期 / 库存不足
- 分类：止痛退烧 / 抗过敏 / 补液 / 营养补充 / 设备耗材 / 其他
- 成员：当前家庭成员
- 存放位置：客厅药箱 / 卧室抽屉 / 儿童药箱 / 其他
- 是否有图片：有图 / 无图

### 排序建议

默认排序建议按处理优先级：

1. 已过期
2. 库存不足
3. 即将过期
4. 其他正常药品

这样打开页面时，最需要处理的药品会自然出现在前面。

## AI 能力边界

### 第一版 AI 能力

AI 继续负责：

- 识别药盒 / 说明书图片
- 回填药品名称、分类、剂量、规格、使用说明、适应症
- 输出摘要
- 输出识别不确定项

### AI 不做的事情

AI 不应承担：

- 诊断
- 替代用药推荐
- 剂量替换建议
- 医疗结论

### AI 输出规则

识别结果必须遵守：

- 能确认的字段才回填
- 不能确认的字段返回空字符串
- 模糊项要进入提醒区
- 明确提示“请以药盒 / 说明书原文为准”

## 风险与提醒

### 有效期提醒

- `<= 0 天`：过期
- `1 ~ 60 天`：即将过期
- `> 60 天`：正常

### 库存提醒

- `quantity = 0`：已用完
- `quantity <= 1`：库存不足

### 安全提醒

建议在卡片和详情中显式展示：

- 过敏相关风险
- 儿童用药需谨慎
- 不要重复叠加同类药
- 已过期药品应尽快处理

## 迁移与兼容

### 现有数据兼容

这一版需要兼容当前已经入库的药品数据：

- 保留旧记录可继续展示
- 没有 `imageBytes` 的记录继续正常显示
- 没有明确 `quantity` 的记录可暂时沿用默认值

### 后续批次升级兼容

未来若引入批次结构，应尽量保持：

- 主记录不变
- 批次作为扩展层
- 当前页面仍可只展示聚合后的总量和风险状态

## 验证标准

本次升级完成后，应该能满足：

1. 用户可以快速搜索真实数据库中的药品
2. 页面可明显看出哪些药品即将过期或已过期
3. 页面可清楚看到药品的存放位置和库存
4. 带图药品能在卡片内直接预览，不跳转页面
5. AI 识别只负责辅助录入，不会自动写入错误内容
6. 未来加入批次时，不需要推倒现有结构

## 实施顺序建议

### 第一阶段

- 增强药品页统计、搜索、筛选和排序
- 强化库存和位置展示
- 继续保留图片内联预览

### 第二阶段

- 补药品详情页
- 补更细的提醒规则
- 补更完整的 AI 提示内容

### 第三阶段

- 视使用情况引入批次结构
- 做多批次库存聚合
- 做更细的入库 / 出库记录

## 结论

本次升级的核心不是“做更多功能”，而是把当前药品管理从“资料卡”推进成“家庭药箱首页”。

最重要的原则是：

- 先稳住单条主记录
- 先让提醒和查找真正有用
- 先让图片和 AI 服务于录入与查找
- 批次能力放到后面平滑升级
