# 药品批次扩展预留说明

## 目的

当前药品管理已经稳定在“单条主记录”模式，本说明只记录未来如果要引入批次管理，应该怎样在不推翻现有页面和数据结构的前提下扩展。

## 现状

当前药品主记录负责：

- 药品名称
- 分类
- 剂量
- 规格
- 使用说明
- 治疗疾病 / 适应症
- 图片
- 所属成员
- 库存数量
- 存放位置
- 过期日期
- 安全提示

这套结构已经足够覆盖家庭药箱的第一阶段需求。

## 未来批次层的职责

如果后续真的要做批次，批次层只负责：

- 批次数量
- 批次购入或录入时间
- 批次有效期
- 批次来源
- 批次备注

批次层不应该替代主记录，也不应该承担药品图片、适应症、成员归属这些主信息。

## 建议的数据边界

### 主记录继续负责

- 药品展示卡
- 搜索关键词
- 图片预览
- AI 识别结果
- 与成员、病历、过敏记录的上下文关联

### 批次层负责

- 库存拆分
- 多盒同名药的分别记录
- 过期时间差异
- 入库来源差异

## 建议的演进顺序

1. 保持当前单条主记录不变。
2. 当真实出现“同名药不同批次”的管理痛点时，再加批次表。
3. 批次数据先在后端聚合，前台仍然以主记录为核心展示。
4. 确认业务需要后，再开放批次编辑界面。

## 不建议现在做的事

- 不要把药品页重构成仓库系统。
- 不要把批次逻辑塞进现有录入弹窗。
- 不要为了“可能会用到”提前增加复杂出入库流程。

## 结论

药品批次是一个后续专案，不是当前主线的一部分。  
当前最重要的是维持单条主记录的清晰度、搜索能力和提醒能力。
