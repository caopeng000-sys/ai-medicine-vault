# 药品管理 Computer Use 回归测试用例

## 目的

这份文档用于 `computer use` 或浏览器自动化回归测试，验证当前仓库中的药品管理主流程没有被改坏。  
重点覆盖：

- 真实数据库搜索
- 药品新增 / 编辑 / 删除
- 图片上传与 AI 识别回填
- 图片内联预览
- 保存后自动关闭弹窗
- 药品状态与排序展示

## 测试前置条件

1. 本地开发服务已启动，访问地址为 `http://localhost:3000`。
2. 本地 PostgreSQL 已连接，`DATABASE_URL` 可用。
3. 至少存在一个成员，优先使用“曹鹏”或 `member-cp`。
4. 浏览器中能正常打开 `/medicines` 页面。
5. 本地准备一张药品图片，建议使用药盒或说明书截图。

## 回归判断标准

满足以下条件时，认为药品管理主流程通过：

- 页面能正常打开，没有白屏或跳转错误。
- 搜索框能命中数据库里的真实药品记录。
- 新增药品后能立即在列表中看到结果。
- 上传图片后可以在弹窗里直接预览。
- 点击图片可以重新选择文件。
- AI 识别后表单能被回填。
- 保存成功后弹窗自动关闭。
- 编辑后记录能被更新。
- 删除后记录能被移除。

## 测试用例

### TC-01 打开药品页并搜索真实数据

**目标**

确认药品页的搜索框已经接到真实数据库，不是前端假筛选。

**步骤**

1. 打开 `http://localhost:3000/medicines`。
2. 在搜索框输入 `布洛芬`。
3. 点击“搜索”按钮或直接回车。
4. 观察页面中是否出现 `布洛芬缓释胶囊`。
5. 清空搜索词，输入 `不存在的药名123`。
6. 再次执行搜索。

**预期结果**

- 输入 `布洛芬` 后能命中真实药品卡片。
- 页面标题中的数量会随搜索结果变化。
- 输入不存在的词时，页面显示“没有找到匹配的药品记录，请换一个关键词试试。”

---

### TC-02 新增药品并上传图片后保存

**目标**

验证新增药品的完整录入链路可用，且图片会一起保存到数据库。

**步骤**

1. 打开 `http://localhost:3000/medicines`。
2. 点击“新增药物记录”或“录入药品”。
3. 选择当前成员。
4. 填写以下信息：
   - 药品名称：`回归测试药品A`
   - 分类：`止痛退烧`
   - 剂量：`0.1g/片`
   - 规格：`0.1g * 10 片`
   - 库存数量：`1 盒`
   - 存放位置：`客厅药箱`
   - 治疗疾病：`用于测试新增流程`
   - 有效期：填写一个未来日期
   - 使用说明：`每天一次`
   - 补充说明：`computer use 回归录入`
   - 安全提醒：`仅用于测试`
5. 上传一张本地药品图片。
6. 观察弹窗中是否立即显示图片预览。
7. 点击“AI 识别图片”。
8. 等待识别完成，检查表单是否被回填。
9. 点击“保存药品”。

**预期结果**

- 图片在弹窗中立即可见。
- 点击图片会再次打开文件选择器。
- AI 识别成功后会回填部分表单字段。
- 点击保存后弹窗自动关闭。
- 新增药品出现在药品列表中。
- 刷新页面后记录仍然存在。

---

### TC-03 编辑药品并保持图片可见

**目标**

确认编辑模式可以保留原记录，并更新字段后正常保存。

**步骤**

1. 在 `/medicines` 页找到 `回归测试药品A`。
2. 点击卡片上的“编辑”按钮。
3. 修改以下内容：
   - 库存数量：从 `1 盒` 改成 `2 盒`
   - 存放位置：改成 `卧室抽屉`
   - 使用说明：改成 `修改后的说明`
4. 保持已有图片不变。
5. 点击“保存修改”。
6. 返回列表页后检查该记录。

**预期结果**

- 编辑弹窗能带出原始值。
- 保存后弹窗关闭。
- 列表中该药品的库存数量和存放位置已经更新。
- 图片预览仍然存在，没有丢失。

---

### TC-04 删除药品记录

**目标**

确认删除操作可用，且删除后列表会刷新。

**步骤**

1. 在 `/medicines` 页找到 `回归测试药品A`。
2. 点击“删除”按钮。
3. 在确认弹窗中确认删除。
4. 观察列表变化。
5. 刷新页面，确认该记录不再出现。

**预期结果**

- 删除前有二次确认。
- 删除后药品卡从列表中消失。
- 刷新页面后记录不再出现。

---

### TC-05 检查药品状态与排序

**目标**

确认页面会优先展示需要处理的药品，而不是乱序。

**步骤**

1. 打开 `http://localhost:3000/medicines`。
2. 查看顶部统计卡是否包含：
   - 药品库总量
   - 即将过期
   - 已过期
   - 库存不足
3. 观察列表前几条药品是否优先展示过期、库存不足或即将过期的记录。

**预期结果**

- 顶部统计卡正常显示。
- 过期或库存不足的药品在列表中更靠前。
- 状态标签和统计卡口径一致。

---

### TC-06 药品图片内联预览

**目标**

确认药品卡上的原图展示不再跳转新页面，而是直接内联显示。

**步骤**

1. 在 `/medicines` 页找到一张带图片的药品卡。
2. 观察卡片里的图片区域。
3. 检查是否仍然出现跳转到单独页面的行为。

**预期结果**

- 图片直接显示在药品卡内部。
- 不需要跳转到新的页面查看原图。
- 页面仍然保持在 `/medicines`。

## 运行建议

如果把这份文档交给 `computer use` 执行，建议按下面顺序跑：

1. TC-01 搜索真实数据
2. TC-02 新增药品并上传图片
3. TC-03 编辑药品
4. TC-04 删除药品
5. TC-05 检查状态与排序
6. TC-06 检查图片预览

这样可以先确认基础可用，再做带写入的回归。

## 失败时的排查线索

- 搜索没命中：先检查 `/medicines?q=关键词` 是否有返回真实结果。
- 图片不显示：先检查图片是否已经成功入库，再看 `/api/medicines/:id/image` 是否返回 `200`。
- 保存后不关闭：先检查弹窗是否触发了 `setOpen(false)` 和 `resetDialog()`。
- 删除后还在：先检查浏览器是否停在旧缓存，刷新后再看数据库是否真的删掉。

## 结论

这份回归文档适合作为 `computer use` 的浏览器执行脚本输入。  
它的目标不是把药品管理所有功能都测完，而是稳定地覆盖主流程，保证药品录入、搜索、图片和 CRUD 不回归。
